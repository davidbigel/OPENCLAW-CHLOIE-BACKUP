# OKF Implementation Roadmap

## Goal

Turn OKF into a working habit for David and Chloe without making the system heavy.

## Phase 1: Now

Focus on the smallest version that works.

### Deliverables

- a clear capture rule
- a clear classification rule
- a raw/processed/durable split
- a simple daily checklist
- a memory hygiene routine
- a NotebookLM usage rule

### What this phase should feel like

- easy
- fast
- readable
- low-friction
- boring in a good way

### What to do now

- Keep capture literal.
- Keep decisions in files.
- Keep raw input unchanged.
- Keep one short question as the default clarification rule.
- Use NotebookLM as a helper, not as the system itself.

## Phase 2: Next

After the basics work, add structure only where it clearly helps.

### Deliverables

- standard folder patterns
- better cross-linking
- stronger memory cleanup
- a more reliable review process
- better source grouping in NotebookLM

### What to improve

- retrieval speed
- correctness
- version control
- traceability
- consistency

### What to avoid

- too many schemas
- too many tags
- too many nested subfolders
- too many rules that nobody follows

## Phase 3: Later

Scale only after the basic loop is stable.

### Possible expansions

- more automated linking
- richer metadata
- per-project knowledge bases
- stronger synthesis reports
- more formal review cycles

### Warning

Do not move into this phase too early.

If the system is not already easy to use, scaling will only multiply the mess.

## Recommended Operating Sequence

1. Capture the item.
2. Classify it.
3. Validate it.
4. Link it.
5. Store it.
6. Retrieve it when needed.
7. Correct it if wrong.
8. Distill what matters into memory.

## Practical Rules

- Raw data stays raw.
- Durable decisions go to durable files.
- Short questions are better than long back-and-forth.
- One good link is better than five weak ones.
- NotebookLM should synthesize, not replace the source system.

## Metrics That Matter

The system is improving if:
- capture is faster
- fewer things get lost
- corrections are easier
- retrieval is quicker
- memory is cleaner
- David has less friction
- Chloe has less guesswork

## Final Recommendation

Start with OKF-Lite.

That means:
- simple intake
- simple classification
- simple durable storage
- simple retrieval
- simple review

If the simple version is working, then add sophistication slowly.
If it is not working, reduce complexity before adding more.
